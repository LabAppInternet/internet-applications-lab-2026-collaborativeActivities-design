## 4. Roles

Every team uses the four cooperative roles below. In a team of five, the fifth
member takes **Quality & CI keeper**. Roles are about *organising* the team; every
member still writes code and owns at least one complete use case, from the entity to
the end-to-end test, and defends it at the end of the course.

| Role | Responsibility | Weeks 1–3 | Weeks 4–6 | Weeks 7–9 |
|---|---|---|---|---|
| **Coordinator** | Runs the weekly meeting, keeps the task board up to date, chases deadlines. | | | |
| **Secretary** | Writes the meeting notes and the decision log; records who committed to what. | | | |
| **Spokesperson** | Speaks for the team in class and to the teaching staff; submits deliverables. | | | |
| **Materials manager** | Keeps the repository, branches, README and shared documents in order. | | | |
| **Quality & CI keeper** *(5th member only)* | Keeps the pipeline green; checks that every merge was reviewed and tested. | | | |

Roles **rotate** at the end of weeks 3 and 6 so that everyone holds at least two
different roles.

## 5. How we work

**Task distribution.** Tasks are split in the weekly meeting and written on the task
board with an owner and a due date. Nobody's work is "done" until it is merged.

**Code review.** Every change reaches `main` through a pull request reviewed by at
least ______ other member(s). Nobody merges their own pull request.

**The Git history is evidence.** Each member commits their own work under their own
GitHub user. Pair-programmed commits name both authors (`Co-authored-by:`).

**When someone is stuck.** A member who is blocked for more than ______ hours asks
the team for help. A member who cannot finish a task says so at least ______ days
before it is due, so the work can be redistributed.

## 8. Conflict resolution

When a disagreement or a breach occurs, we follow these steps **in order**, and the
secretary records each step with its date:

1. **Direct conversation** with the person involved, within ______ days.
2. **Team meeting** on the issue, with a written agreement about what changes and by
   when.
3. **Written notice** to the member, copied to the whole team.
4. **Mediation by the teaching staff** (Josep Roure, Alfredo Rueda). Bring the notes of
   steps 1–3.

Technical disagreements (how to design something) are settled by a short written
decision-log entry — context, options, choice, reason — and, if there is still no
consensus, by ______________________ (e.g. majority vote, the owner of the use case
decides).

## 9. Quality standards

- The pipeline on `main` stays green. Whoever breaks it fixes it first.
- Every use case is delivered with its tests; the acceptance suite is never edited.
- Design decisions are recorded in the decision log.
- Deliverables are reviewed by at least one other member before submission.
