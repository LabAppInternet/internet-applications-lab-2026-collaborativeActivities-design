# Code listing — "Which lines hit the database, and when?"

Projected in class and handed out on paper. **There is no project to run** — reason
about the listing and record your predictions on the *prediction sheet*.

> `Product` is a JPA `@Entity` whose `id` is generated by the database when the row is
> inserted. You will map an entity like this yourself next session; today, take the
> mapping as given.

The whole method below runs inside **one** transaction (`@Transactional`). Read it
line by line and decide, for each numbered line, whether it sends SQL to the database
and *when*.

```java
@Service
class CatalogDemo {

    private final ProductRepository productRepository;

    CatalogDemo(ProductRepository productRepository) {
        this.productRepository = productRepository;
    }

    @Transactional                                                    // one transaction
    public void showLifecycle() {
        Product product = new Product("FM Radio");                    // 1
        productRepository.save(product);                              // 2
        Product found = productRepository.findById(product.getId())   // 3
                                         .orElseThrow();
        found.setName("DAB Radio");                                   // 4
    }                                                                 // 5  method returns → commit
}
```

Two questions to hold in mind as you predict:

- **Line 3:** is `found` the *same object* as `product`? What would that tell you about
  whether a `SELECT` had to run?
- **Line 4:** you changed a field but never called `save()`. Does the change reach the
  database — and if so, *when*?

## Why you can see the SQL at all

The seed project turns on SQL logging in `application.properties`:

```properties
# print every SQL statement Hibernate sends...
logging.level.org.hibernate.SQL=DEBUG
# ...formatted, and with the bound parameter values
logging.level.org.hibernate.orm.jdbc.bind=TRACE
spring.jpa.properties.hibernate.format_sql=true
```

Without these lines the application behaves identically — you just wouldn't see the
statements. Reading this log is a habit you will use all term (concurrency and the N+1
problem are both diagnosed from it).

## How to read the log

Each statement Hibernate emits starts with a keyword:

- `insert into ...` — a new row is written.
- `select ...` — a read.
- `update ... set ... where id=?` — an existing row is changed.

Count them, and note **where in the method** each one appears relative to the numbered
lines. Some lines emit nothing; at least one statement appears only when the
transaction **commits**, after line 5.

## Bonus (for fast groups)

After `showLifecycle()` returns, the transaction is closed and `product` is now
**detached**. Predict what these two extra lines do:

```java
product.setName("Retro Radio");     // 6  (no save call)
productRepository.save(product);     // 7  save() on a detached entity
```
